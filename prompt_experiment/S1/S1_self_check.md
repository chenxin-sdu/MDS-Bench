# S1: Global Self-Check (Revise All JSON Content)

You are a global quality inspector for medical data standardization results. Treat the `agent1_data_organization` generated by S0 as a draft. Without reading any final answers or evaluation results, review all samples field by field, and output an S1 directory that is ready for direct evaluation.

## 0. Strict Experimental Constraints

1. **Do not read or use** the following files:
   - `{dataset_root}/VLM/ground_truth*.json`
   - `{dataset_root}/VLM/eval_results*.json`
   - `{dataset_root}/prompt_experiment/**/eval_results*.json`
   - Any files containing final evaluation scores, GT annotations, standard answers, or human answer leakage.
2. First fully copy the S0 output directory to the S1 output directory, then modify the S1 copy; **do not modify S0 in place**.
3. Revise only based on the following evidence:
   - The S0 output directory;
   - `{dataset_root}/data` raw data;
   - `{dataset_root}/VLM/random.txt` sample manifest;
   - `{dataset_root}/prompt_experiment/S0/Data_Organization_Agent.md` the format specification file for the Data Organization Agent.
4. For fields with insufficient evidence, do not guess, and do not infer diagnoses/labels from medical image appearance; keep the original value or fill `null` / `NA` / `unknown`, and record `action="kept"` with the reason in the report.
5. Output JSON must not retain any `*__desc` or `*__options` fields.

## 2. Structural Specifications That Must Be Preserved

Each sample JSON top level must be an object and contain:

```text
record
context
media_geometry
tasks
provenance
```

Key hard constraints:

1. `record.image_path` must be a relative path of the form `images/<idx>.<png|jpg|jpeg>`, and the file must actually exist and be openable.
2. `standardized_annotations/<idx>.json` and `images/<idx>.<ext>` must correspond one-to-one by index.
3. `media_geometry.media.task_type` can only be `classification`, `segmentation`, or `detection`.
4. After normalization, `media_geometry.media.dimension` can only be `2D`, `3D`, or `video`.
5. Keep only one valid spatial branch by dimension:
   - `2D` → `media_geometry.spatial.common` is non-empty; `three_d` and `video` are empty objects;
   - `3D` → `media_geometry.spatial.three_d` is non-empty; `common` and `video` are empty objects;
   - `video` → `media_geometry.spatial.video` is non-empty; `common` and `three_d` are empty objects.
6. Keep only one valid task branch by task:
   - `classification` → `tasks.classification` is non-empty; other task branches are empty objects;
   - `segmentation` → `tasks.segmentation` is non-empty; other task branches are empty objects;
   - `detection` → `tasks.detection` is non-empty; other task branches are empty objects.
7. Use `null` / `NA` / `unknown` for unknown field values; do not fabricate.

## 3. Global Self-Check Procedure

Execute in the following order; do not skip steps.

### Step 1: Copy and Inventory

1. Fully copy S0's `agent1_data_organization` to the S1 directory.
2. Build the target sample index set from `random.txt`.
3. Inventory in S1:
   - Files under `images/`;
   - `standardized_annotations/*.json`;
   - `data_meta.json`.
4. Record missing items, duplicates, index misalignment, and leftover old files.

### Step 2: Per-Sample, Per-Field Review

Open every JSON under `standardized_annotations/`. For each field, check at least once along the following 7 dimensions:

1. **Source Selection Accuracy**: Whether the true source file/case/series in `random.txt` or raw data can be traced from positions such as `context.sample.extra`, `raw`, `provenance.notes`. Do not fabricate sources when evidence is insufficient.
2. **Coverage**: Whether image and JSON both exist, are readable, and have consistent indices; whether `record.image_path` points to a real image.
3. **Schema Validity**: Whether top-level blocks, required fields, field types, active/inactive branches, and `__desc/__options` cleanup comply with the specification.
4. **Semantic Correctness**: Whether `task_type`, `dimension`, modality, anatomical structure, and task branches are semantically consistent with the raw data and annotations.
5. **Information Quality**: Whether `extra` and the task payload contain useful information; remove clearly placeholder or contradictory fields; retain real, traceable information.
6. **Content Fidelity**: Whether classification labels, detection boxes, segmentation masks/COCO, source paths, sample IDs, etc. faithfully come from raw data or original annotations.
7. **Dataset Metadata Quality**: Whether this sample is consistent with the aggregation in `data_meta.json`.

### Step 3: Allowed Revision Actions

When evidence is sufficient, you may:

- Rewrite the entire content of a sample JSON;
- Correct `record.image_path`, task type, dimension, spatial branch, task branch, labels, class IDs, source fields, modality, anatomical structure, etc.;
- Regenerate or correct image files, but indices must remain aligned with JSON;
- Rebuild `data_meta.json` so that it is consistent with all S1 samples.

For annotation fields such as medical diagnosis, class, mask, and box, there must be support from original annotation files, filename conventions, metadata, or reliable evidence in S0; if there is no evidence, keep the original value or fill as unknown.

### Step 4: Rebuild data_meta.json

`data_meta.json` must be aggregated from the final S1 samples. At least review:

- `dataset_name`
- `modality_primary`
- `modality_secondary`
- `anatomical_structure`
- `data_volume.total`
- `data_volume.label`
- `valid_image_n.total`
- `task_type`
- `num_classes_per_task`
- `label_presence`

Among these, `data_volume.total` should equal the final number of valid sample JSONs; `valid_image_n.total` should equal the number of openable images; `task_type` should cover the task types that actually appear in the final samples.

## 4. Pre-Delivery Self-Check

Before submission, confirm again:
1. The S0 directory has not been modified.
2. There is no trace of reading/referencing ground truth or eval results in S1.
3. Every sample JSON can be parsed by `json.load`.
4. Every `record.image_path` can find the corresponding file under S1 `images/`.
5. `data_meta.json` is consistent with the final sample and image counts.
